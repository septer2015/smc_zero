# smc-zero

Проект даёт основу для бэктеста по SMC (Smart Money Concepts, «концепции умных денег»).
Стратегия работает с тремя таймфреймами: **D1**, **H1** и **M15**. Незнакомые термины раскрыты
в разделе [«Глоссарий»](#глоссарий) в конце документа.

## Обзор

**D1** задаёт общий bias (направленность старшего таймфрейма). Здесь же лежат PDH/PDL (максимум
и минимум прошлого дня) и крупные order blocks (блоки ордеров).

**H1** — рабочая структура. На этом таймфрейме ищем BOS (Break of Structure, слом структуры по
тренду) и CHoCH (Change of Character, смена характера — слом против тренда). Здесь же работает
правило premium/discount (зона премии и дисконта относительно равновесия). Сюда же относятся
сессии.

**M15** — зона входа. Порядок такой: sweep (снятие ликвидности) → CHoCH → вход в FVG (Fair
Value Gap, зона дисбаланса) или OB (Order Block, блок ордеров) на M15 внутри зоны H1.

**M5** не используется. **H4** участвует только в bias (направленности) старших таймфреймов
(HTF, Higher Timeframe): `BiasConfig.timeframes` по умолчанию равен `("H1", "H4", "D1")`
(SPEC_SMC.md C5). Как таймфрейм входа H4 не используется никогда.

## Конвенция времени

В файлах `./data/*.csv` (M15, H1, D1) колонка `datetime` содержит штамп **open_time**, то есть
момент открытия бара. Время указано в UTC без зоны (UTC-naive), поэтому
`close_time = timestamp + период бара`. Последний бар каждого таймфрейма считается ещё не
закрытым и по умолчанию отбрасывается (флаг `drop_unclosed=True`). Так проект защищается от
тонкого lookahead (подглядывания в будущее) на живом крае ленты.

## Быстрый старт

Установите пакет с инструментами разработки и оптимизатором:

```bash
pip install -e ".[dev,optimize]"
```

Запустите один бэктест по окну, которое задаёте сами. Все пороги берутся из проектной
конфигурации. Окно — это целые сутки UTC от `--start` до `--end` включительно:

```bash
smc-backtest --symbol EURUSD --start 2022-08-15 --end 2022-09-15
```

Без установки тот же запуск можно выполнить из корня репозитория. Python должен видеть и пакет
`src`, и пакет раннеров:

```bash
PYTHONPATH=src python -m scripts.run_backtest --symbol EURUSD --start 2022-08-15 --end 2022-09-15
```

Оптимизация идёт по walk-forward-фолдам (скользящим окнам обучения с проверкой на данных,
которых модель не видела), после чего победитель запускается один раз и попадает в отдельный
отчёт:

```bash
smc-optimize --symbol EURUSD --n-trials 100 --jobs 4
```

Отчёты складываются в `./reports/`:

* `backtest_<symbol>_<tf>_<start>_<end>/` — `trades.csv` / `trades.parquet` и `summary.txt`;
* `optimization_<symbol>_<tf>_<start>_<end>_n<trials>/` — те же два файла для победителя, плюс
  `best_params.json` (параметры, счёт, его `score_metric` и `penalty_power`, агрегаты фолдов) и
  `fold_metrics.csv` (таблица обучения и проверки по каждому фолду, со строками `mean` и `sigma` —
  на строках `mean` лежат ещё `train_profit_mean`, `test_profit_mean` и
  `degradation_ratio` запуска).

Каждый запуск помечается признаком наличия издержек. Издержки приходят из профиля брокера
`BrokerSpec` (SPEC_SMC.md §7.18): штамп `has_costs` выключается только тогда, когда все три
параметра профиля — `spread_pip`, `commission_per_lot_usd`, `slippage_pip` — равны нулю, и тогда
сводка пишет об этом прямо. Спред и слиппедж списываются так же, как комиссия: рабочий конфиг
`configs/live_eurusd_m15.yaml` задаёт счёт Альфа-Форекс с комиссией `0.00`, и правило 4 он не
нарушает. Кривую капитала нельзя принимать за прибыль (C6, §5 п.10).

Запуск с числами победителя оптимизации берёт их из конфигурационного файла. Флаг `--config-path`
читает YAML с блоками `strategy`, `broker` и `backtest`, а аргумент командной строки перебивает
файл:

```bash
smc-backtest --config-path configs/live_eurusd_m15.yaml --start 2022-08-15 --end 2022-09-15
```

Для подготовки к реальной торговле читайте
[`docs/LIVE_TRADING_GUIDE.md`](docs/LIVE_TRADING_GUIDE.md).

Длина окна заметно влияет на время счёта. Цепочка входа Э4' обходила каждый уровень окна бар за
баром, поэтому её время росло примерно как квадрат длины окна. Замеры на `./data/EURUSD_M15.csv`
до Э9': 5 дней — 0.3 с, 1 месяц — 6 с, 3 месяца — 58 с, 1 год — 16 минут (`937.9 с`). Векторная
цепочка Э9' (SPEC_SMC.md §7.13) считает те же правила намного быстрее: тот же год — 1.2–1.9 с,
вся четырёхлетняя лента — 9.7–17.3 с. Поэтому и рабочее окно, и оптимизация по нему стали
доступны. Сетка фолдов по умолчанию — 15 фолдов по 60 дней (SPEC_SMC.md §7.10 п.62).
Начинайте с месяца или квартала и задавайте свои издержки, потому что запуск без издержек
помечается правилом 4.

## Запуск длительных процессов

Длительные процессы — оптимизацию, бэктест на полном периоде, запуски на несколько часов —
запускайте ТОЛЬКО под `nohup`. Тогда они переживут закрытие терминала и обрывы связи. Пример:

```bash
nohup env PYTHONPATH=src .venv/bin/python -m scripts.run_optimization \
  --symbol EURUSD --start 2022-08-15 --end 2026-09-22 \
  --n-trials 100 --jobs 2 --seed 42 --report-dir ./reports/full_run \
  > /tmp/opt_run.log 2>&1 &
```

Мониторинг: `tail -f /tmp/opt_run.log` и `grep -c 'Trial.*finished' /tmp/opt_run.log`.
Остановка: `kill <PID>`. PID печатается при запуске, а если потеряли — ищите через
`ps aux | grep run_optimization`.

Это правило обязательно для всех будущих запусков.

## Что уже сделано

Реализованы следующие слои.

Данные — `data_loader.py`: конвенция open_time, сшивка старшего таймфрейма (HTF) и младшего
(LTF) по закрытому бару.

Индикаторы — `indicators/structure.py` (свинги и BOS/CHoCH), `fvg.py`, `liquidity.py` (sweep),
`impulse.py` (фильтр импульса), `sessions.py` (killzone — торговые окна сессий), `bias.py` (bias по
H1/H4/D1), `levels.py` (PDH/PDL, PWH/PWL, PMH/PML и диапазоны азиатской, лондонской и
нью-йоркской сессий с фильтрами доступности и жизненным циклом fresh/broken).

Стратегия — `strategy/intents.py`: цепочка входа M15 из SPEC_SMC.md §7.8, `sweep -> CHoCH ->
displacement -> FVG limit`. Один интент на принятый бар (побеждает самый значимый уровень бара),
плюс журнал отказов. `strategy/take_profit.py`: ближайший видимый уровень ликвидности с фолбэком
по RR. `strategy/risk_gate.py`: проверка маржи по C7 и процент риска для набора интентов.

Бэктестер — `backtester/engine.py`: событийный движок из SPEC_SMC.md §7.9. Лимит исполняется на
баре после сигнала. Стоп проверяется раньше цели. Издержки модели C6 списываются как спред и своп,
плюс комиссия и слиппедж профиля. Маржинальный фильтр C7 проверяется по текущей equity. Для каждого
интента, не ставшего сделкой, есть строка в журнале. `backtester/metrics.py`: таблица метрик.
`backtester/reports.py`: текстовая сводка и экспорт журнала сделок.

Walk-forward — `backtester/walkforward.py`: разбиение одной ленты на обучение и проверку (Э6').
`split_walkforward` режет якорные расширяющиеся фолды по умолчанию и скользящие при
`anchored=False`. Это позиционные срезы кадра заказчика, поэтому фолд никогда не делит бар со
своим окном обучения. `aggregate_fold_metrics` отдаёт среднее и сигму по генеральной совокупности
для шести главных метрик. `run_walkforward` соединяет фолды с движком Э5' при фиксированных
издержках и без оптимизации (подбор параметров — это Э7').

Оптимизатор — `optimizer/`: поиск из SPEC_SMC.md §7.11 (Э7'). `build_tape_marks` кэширует
разметку bias старших таймфреймов и книгу уровней один раз на запуск для всех триалов
исследования. `score_from_aggregates` ранжирует один набор параметров по фолдам проверки: ведущая
метрика агрегата walk-forward умножается на профит проверки и делится на просадку, а при
`penalty_power` заказчика ещё приглушается тем, сколько прибыли обучения дожило до проверки. Окно
проверки, не заработавшее денег, получает ровно ноль, поэтому убыточный набор никогда не обгонит
прибыльный. `run_optimization` максимизирует этот счёт на исследовании TPE с фиксированным seed по
диапазонам `PARAM_RANGES` и заново переоценивает победителя по всем фолдам. `cache_mismatches`
отказывает конфигурации, из которой кэш не строился. optuna импортируется лениво, фабрикой
исследования, поэтому слой и его тесты работают и без неё.

Консоль — `scripts/`: раннеры Э8'. `smc-backtest` выполняет один запуск фиксированной
конфигурации по окну `./data` и пишет отчёт. `smc-optimize` проводит исследование Э7' по
walk-forward и затем отчитывается о победителе. Оба пишут в `./reports`, у обоих свой контракт
argparse. Ни один из них не задаёт порог и не пересчитывает метрику (SPEC_SMC.md §7.12).

Данные лежат в `./data/`, отчёты — в `./reports/`.

## Источники данных

Лента приходит из двух баз, их выбирает флаг `--data-source`:

- `project` (по умолчанию) — папка `./data` с раскладкой `datetime,open,high,low,close,volume`;
- `mt5` — сырой экспорт MetaTrader 5 «Bars»
  (`symbol,timeframe,time,open,high,low,close,tick_volume,spread,real_volume`).

Имя файла одно в обеих базах: `<SYMBOL>_<TIMEFRAME>.csv`, например `EURUSD_M15.csv`. Базу MT5
задаёт переменная `SMC_DATA_DIR`; без неё берётся `$HOME/_data/mt5` (то есть `~/_data/mt5`, а на
этой машине — `/home/com/_data/mt5/`). Раскладку `load_ohlcv` определяет по именам колонок,
поэтому переводить выгрузку руками не нужно. D1 в экспорте MT5 — голая дата, M15 и H1 — полный
штамп времени.

Запуск прямо на свежем экспорте брокера:

```bash
SMC_DATA_DIR=~/_data/mt5 smc-backtest --symbol EURUSD --timeframe M15 \
  --start 2022-08-15 --end 2026-09-22 --data-source mt5
```

Повторный штамп времени в свежем экспорте не роняет запуск: побеждает поздняя строка
(`merge_ohlcv` в `smc_zero.data_loader`). Так четыре года проектной ленты и длинный экспорт
брокера становятся одной лентой без ручной конвертации.

Подробности — SPEC_SMC.md §7.20.

## Ежедневный режим

Ежедневные сигналы готовит скрипт `scripts/daily_signal_check.sh`. Он читает ленту из свежего
экспорта MetaTrader 5 (флаг `--data-source mt5`, база `SMC_DATA_DIR`), запускает бэктест за
последние четыре года до текущей даты под `nohup`, кладёт отчёт в `./reports/daily_<ГГГГММДД>` и
печатает сделки, открытые с 22:00 MSK вчерашнего дня. Автоматического исполнения нет: сигналы
человек исполняет вручную и записывает результат в `docs/TRADING_JOURNAL.md`.

Скрипт берёт базу экспорта из переменной `SMC_DATA_DIR`, а по умолчанию читает `$HOME/_data/mt5`
(на этой машине — `/home/com/_data/mt5/`):

```bash
cd /home/com/work2/python/cfd/project/smc_zero
SMC_DATA_DIR=/home/com/_data/mt5 ./scripts/daily_signal_check.sh
```

Повторно напечатать сигналы готового отчёта, без нового бэктеста, можно так:

```bash
SMC_REPORT_FOLDER=./reports/daily_20261002/backtest_EURUSD_M15_2022-10-02_2026-10-02 \
  ./scripts/daily_signal_check.sh
```

Запуск по расписанию (будни, 22:00 MSK) оформляется строкой cron. Пути в строке ниже приведены
для этой машины; на другом окружении подставьте свои. Лог складывается в `/tmp/cron_smc.log`:

```
0 22 * * 1-5 SMC_DATA_DIR=/home/com/_data/mt5 /home/com/work2/python/cfd/project/smc_zero/scripts/daily_signal_check.sh >> /tmp/cron_smc.log 2>&1
```

Перед запуском убедитесь, что в папке экспорта лежат свежие `EURUSD_M15.csv` и, если они нужны
стратегии, `EURUSD_H1.csv` и `EURUSD_D1.csv`. Обновление выгрузки описано в разделе
[«Источники данных»](#источники-данных).

## Глоссарий

### Торговые концепции

- **SMC (Smart Money Concepts)** — подход к анализу рынка, который ищет следы крупных участников
  в структуре цены: сломы структуры, зоны дисбаланса и скопления ликвидности.
- **Bias** — направленность старшего таймфрейма, общий вектор рынка. Старший таймфрейм задаёт
  предпочтительное направление сделок, младший уточняет точку входа.
- **BOS (Break of Structure)** — слом структуры: закрытие цены за последний свинг по направлению
  тренда. Подтверждает продолжение движения.
- **CHoCH (Change of Character)** — смена характера движения: закрытие цены против тренда,
  которое ломает контр-свинг. Сигнализирует о возможной смене направления.
- **FVG (Fair Value Gap)** — зона дисбаланса, то есть трёхсвечный разрыв, где цена прошла без
  встречной торговли. Бычий FVG: `low[i+1] > high[i-1]`, медвежий — наоборот.
- **Order Block (OB)** — блок ордеров: последняя противоположная свеча перед импульсом, который
  дал BOS или CHoCH. Блок считают валидным, если импульс оставил смещение цены (displacement)
  или FVG.
- **Liquidity** — ликвидность: уровни скопления стоп-ордеров и лимитных заявок (равные максимумы
  и минимумы, PDH/PDL, границы сессий). Цена часто идёт к таким уровням.
- **Sweep** — снятие ликвидности (ложный пробой): тень выходит за уровень, а закрытие свечи
  возвращается внутрь. За снятием ликвидности обычно следует разворот.
- **Killzone** — активное торговое окно сессии (Лондон, Нью-Йорк), когда объём и волатильность
  повышены. В проекте задаётся в `indicators/sessions.py`.
- **Premium/Discount** — зона премии и дисконта относительно равновесия диапазона последнего
  структурного свинга. Лонг ищут в дисконте (ниже середины), шорт — в премии (выше середины).
- **PDH/PDL (Previous Day High/Low)** — максимум и минимум предыдущего дня. Служат целями и
  уровнями ликвидности.
- **AsianH/L, LondonH/L, NYH/L** — максимум и минимум азиатской, лондонской и нью-йоркской
  сессий. Используются как сессионные уровни ликвидности.

### Таймфреймы и структура

- **HTF (Higher Timeframe)** — старший таймфрейм, на котором задаётся bias. В проекте это H4
  и D1.
- **LTF (Lower Timeframe)** — младший таймфрейм, на котором ищут точку входа. В проекте это M15.
- **D1, H1, M15** — дневной, часовой и 15-минутный таймфреймы. D1 задаёт bias, H1 даёт рабочую
  структуру, M15 служит зоной входа.
- **Swing (свинг)** — локальный экстремум: максимум или минимум с N свечей слева и справа.
  Свинг подтверждается закрытием правой свечи и известен только с этого момента.

### Метрики и параметры

- **Pip (пункт)** — минимальный шаг котировки; для EURUSD равен 0.0001.
- **Lot (лот)** — стандартный торговый объём; один лот равен 100 000 единиц базовой валюты.
- **RR (Risk/Reward)** — соотношение риска и прибыли. Показывает, во сколько раз возможная
  прибыль превышает риск по сделке.
- **Win Rate (доля прибыльных сделок)** — отношение числа прибыльных сделок к общему числу
  сделок, в процентах.
- **Profit Factor (фактор прибыли)** — отношение суммарной прибыли к суммарному убытку. Значение
  выше единицы означает прибыль на длинной дистанции.
- **Max Drawdown (максимальная просадка)** — наибольшее падение equity от пика, в процентах.
- **Sharpe Ratio (коэффициент Шарпа)** — доходность с поправкой на риск: отношение средней
  доходности к её волатильности. Чем выше, тем ровнее кривая капитала.

### Издержки

- **Spread (спред)** — разница между ценой покупки (ask) и ценой продажи (bid). Списывается с
  каждой сделки.
- **Slippage (проскальзывание)** — исполнение по цене хуже ожидаемой. Возникает на быстром рынке.
- **Swap (своп)** — плата брокера за перенос открытой позиции на следующий день.
- **Commission (комиссия)** — вознаграждение брокера за сделку. У счёта Альфа-Форекс комиссия
  равна нулю, заработок идёт со спреда.

### Разработка и тестирование

- **Walk-forward** — скользящая оптимизация с валидацией: параметры подбирают на одном окне
  (обучение), а проверяют на следующем, которое модель не видела.
- **OOS (Out-of-Sample)** — выборка для проверки вне оптимизации. Показывает, работает ли
  стратегия на данных, которые не участвовали в подборе.
- **Intent (намерение)** — кандидат в сделку: описание входа, которое цепочка правил построила,
  но движок ещё не превратил в сделку.
- **Gate (гейт)** — условие проверки, фильтр. Гейт может пропустить или отклонить кандидата,
  например по риску или по доступности уровня.
