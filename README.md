# smc-zero

Проект даёт основу для бэктеста по SMC (Smart Money Concepts, «концепции умных денег»).
Система работает в двух режимах, и режим выбирает один параметр конфигурации:
консервативный **D1 → H1 → M15** и агрессивный **H4 → M15 → M5**. Незнакомые термины раскрыты
в разделе [«Глоссарий»](#глоссарий) в конце документа.

## Обзор

Система ищет точки входа по SMC (Smart Money Concepts, «концепции умных денег»). Логика общая
для обоих режимов: цена снимает ликвидность за значимым уровнем (sweep), затем ломает структуру
(BOS или CHoCH), после чего вход идёт в зону дисбаланса (FVG) внутри старшей зоны.

Система работает в двух режимах. Режим выбирает один параметр конфигурации, поэтому движок,
издержки, метрики и отчёты у режимов общие: меняется только иерархия таймфреймов.

### Режим A — консервативный (по умолчанию)

Иерархия **D1 → H1 → M15**.

* **D1** задаёт глобальный bias (направленность рынка). На этом таймфрейме лежат PDH/PDL
  (максимум и минимум прошлого дня) и крупные блоки ордеров — Order Block (OB).
* **H1** задаёт рабочую структуру. Система ищет здесь BOS (Break of Structure, слом структуры
  по тренду), CHoCH (Change of Character, смена характера) и применяет правило premium/discount
  (зона премии и дисконта относительно равновесия диапазона). Здесь же работают сессии.
* **M15** даёт точку входа. Система проходит цепочку: sweep (снятие ликвидности) → CHoCH →
  вход в FVG (Fair Value Gap, зона дисбаланса) или OB на M15 внутри зоны H1.

Сделок мало, поэтому качество сигнала выше: около 2–3 сделок в месяц. Режим проверен на четырёх
годах данных (2022-08-15 … 2026-09-22). Конфигурация — `configs/live_eurusd_m15.yaml`, пресет
иерархии — `D1_H1_M15`. Это режим по умолчанию: ключ `hierarchy` в конфиге можно не указывать.

### Режим B — агрессивный (вторая иерархия)

Иерархия **H4 → M15 → M5**.

* **H4** вместе с **D1** задаёт bias.
* **M15** задаёт рабочую структуру — тот же слой структуры, что и в режиме A, но здесь он служит
  опорой для более мелкого входа.
* **M5** даёт точку входа по той же цепочке правил.

Сделок больше, поэтому выборки набираются быстрее. Пипсовые пороги система переносит с M15 и под
волатильность пятиминутных баров ещё не подбирает, поэтому часть сигналов отсекают гейты
реалистичного стопа и спреда. Конфигурация — `configs/live_eurusd_m5.yaml`, пресет иерархии —
`H4_M15_M5`. Ограничения режима описаны в разделе «Быстрый старт» и в «Результатах бэктеста».

### Как переключить режим

Режим задаёт один параметр в YAML-конфиге:

```yaml
hierarchy: H4_M15_M5
```

Без этого ключа работает режим A (`D1_H1_M15`). Тот же выбор доступен флагом командной строки
`--hierarchy H4_M15_M5`. Флаг фиксирует входной таймфрейм: если рядом указать несовпадающий
`--timeframe`, запуск откажется стартовать вместо того, чтобы гадать.

Термины SMC и внутренние понятия раскрыты в разделе [«Глоссарий»](#глоссарий).

## Конвенция времени

В файлах `./data/*.csv` (M5, M15, H1, H4, D1) колонка `datetime` содержит штамп **open_time**,
то есть момент открытия бара. Время указано в UTC без зоны (UTC-naive), поэтому
`close_time = timestamp + период бара`. Последний бар каждого таймфрейма считается ещё не
закрытым и по умолчанию отбрасывается (флаг `drop_unclosed=True`). Так проект защищается от
тонкого lookahead (подглядывания в будущее) на живом крае ленты.

## Быстрый старт

Установите пакет по инструкции раздела [«Установка»](#установка), затем выберите режим.

### Режим A: бэктест на M15 (по умолчанию)

Запустите один бэктест по окну, которое задаёте сами. Все пороги система берёт из проектной
конфигурации. Окно — это целые сутки UTC от `--start` до `--end` включительно:

```bash
smc-backtest --symbol EURUSD --hierarchy D1_H1_M15 \
  --start 2022-08-15 --end 2022-09-15
```

Без установки тот же запуск можно выполнить из корня репозитория. Python должен видеть и пакет
`src`, и пакет раннеров:

```bash
PYTHONPATH=src python -m scripts.run_backtest --symbol EURUSD \
  --start 2022-08-15 --end 2022-09-15
```

С числами победившей оптимизации и полным окном четырёх лет:

```bash
smc-backtest --config-path configs/live_eurusd_m15.yaml \
  --start 2022-08-15 --end 2026-09-22
```

### Режим B: бэктест на M5 (вторая иерархия)

Конфигурация сама задаёт окно и пресет иерархии, поэтому команда короче:

```bash
smc-backtest --config-path configs/live_eurusd_m5.yaml \
  --hierarchy H4_M15_M5 --data-source mt5
```

Флаг `--hierarchy` фиксирует входной таймфрейм: если рядом указать несовпадающий `--timeframe`,
запуск откажется стартовать вместо того, чтобы гадать. Ленту для режима B читайте из папки
`/home/com/_data/mt5/` (по умолчанию `$HOME/_data/mt5`): нужны свежие `EURUSD_M5.csv`,
`EURUSD_M15.csv`, `EURUSD_H4.csv` и `EURUSD_D1.csv`. Перед прогоном ленту проверяет
`smc-check-tape` (см. раздел [«Источники данных»](#источники-данных)).

> **Предупреждение.** Пипсовые пороги режима B перенесены с M15 и под волатильность пятиминутных
> баров ещё не подобраны, поэтому часть сигналов отсекают гейты реалистичного стопа и спреда.
> В базовом прогоне медианный риск на сделку вышел 3.15 % — выше порога предупреждения 2 %.
> Числа режима B читайте как отправную точку для оптимизации, а не как подтверждение
> прибыльности.

### Оптимизация

Оптимизация идёт по walk-forward-фолдам (скользящим окнам обучения с проверкой на данных,
которых модель не видела), после чего победитель запускается один раз и попадает в отдельный
отчёт:

```bash
smc-optimize --symbol EURUSD --n-trials 100 --jobs 2
```

Отчёты складываются в `./reports/`:

* `backtest_<symbol>_<tf>_<start>_<end>/` — `trades.csv` / `trades.parquet` и `summary.txt`;
* `optimization_<symbol>_<tf>_<start>_<end>_n<trials>/` — те же два файла для победителя, плюс
  `best_params.json` (параметры, счёт, его `score_metric` и `penalty_power`, агрегаты фолдов) и
  `fold_metrics.csv` (таблица обучения и проверки по каждому фолду, со строками `mean` и `sigma` —
  на строках `mean` лежат ещё `train_profit_mean`, `test_profit_mean` и
  `degradation_ratio` запуска).

Оптимизация режима B берёт своё пространство параметров и свой счёт, а не те, что использует
режим A. И то, и другое система выбирает по входному таймфрейму, а флаги перебивают выбор:

```bash
env SMC_DATA_DIR=/path/to/mt5 \
  smc-optimize --config-path configs/live_eurusd_m5.yaml --data-source mt5 \
    --n-trials 100 --jobs 2 --ranges m5 --score m5 --target-trades 25 --min-trades 10
```

`--ranges m5` двигает четыре параметра, которые меняют смысл на пятиминутных барах: три барных
окна (`fvg_lookback`, `choch_wait_bars`, `signal_max_age_bars`) и гейт реалистичного стопа
(`min_sl_realistic_pip`). Импульсный порог `displacement.atr_mult_min` в поиск не входит: он
участвует в построении разметки, а разметка строится один раз на базовой конфигурации
(спецификация, §7.22 п.122). `--score m5` ранжирует набор по **пулу**
фолдов проверки: `фактор прибыли пула × min(1, trades / 25)`. Фактор считают только фолды от трёх
сделок, а счёт падает до нуля ниже десяти сделок за период проверки, при убытке пула и при менее
чем пяти плотных фолдах. Значения по умолчанию (`--ranges auto`, `--score auto`) сами выбирают
профиль `m5` для ленты M5 и прежний профиль для M15.


Каждый запуск получает признак наличия издержек. Издержки система берёт из профиля брокера
`BrokerSpec` (см. спецификацию проекта): признак `has_costs` выключается только тогда, когда все
три параметра профиля — `spread_pip`, `commission_per_lot_usd`, `slippage_pip` — равны нулю,
и тогда сводка пишет об этом прямо. Спред и слиппедж система списывает так же, как комиссию:
рабочий конфиг `configs/live_eurusd_m15.yaml` задаёт счёт Альфа-Форекс с комиссией `0.00`,
поэтому правило проекта «без издержек результата нет» он не нарушает. Кривую капитала нельзя
принимать за прибыль: она показывает движение средств, а не итог с учётом издержек.

Числа победившей оптимизации приходят из конфигурационного файла. Флаг `--config-path` читает YAML
с блоками `strategy`, `broker` и `backtest`, а аргумент командной строки перебивает файл.

Для подготовки к реальной торговле читайте
[`docs/LIVE_TRADING_GUIDE.md`](docs/LIVE_TRADING_GUIDE.md).

Длина окна заметно влияет на время счёта. Прежняя цепочка входа обходила каждый уровень окна бар
за баром, поэтому её время росло примерно как квадрат длины окна: замеры на
`./data/EURUSD_M15.csv` давали 5 дней — 0.3 с, 1 месяц — 6 с, 3 месяца — 58 с, 1 год — 16 минут
(937.9 с). Векторная цепочка считает те же правила намного быстрее: тот же год — 1.2–1.9 с, вся
четырёхлетняя лента — 9.7–17.3 с. Поэтому рабочее окно и оптимизация по нему стали доступны
(подробности — в спецификации проекта). Сетка фолдов по умолчанию — 15 фолдов по 60 дней.
Начинайте с месяца или квартала и задавайте свои издержки: запуск без издержек система помечает
отдельным признаком.

## Запуск длительных процессов

Длительные процессы — оптимизацию, бэктест на полном периоде, запуски на несколько часов —
запускайте ТОЛЬКО под `nohup`. Тогда они переживут закрытие терминала и обрывы связи. Пример:

```bash
nohup env PYTHONPATH=src .venv/bin/python -m scripts.run_optimization \
  --symbol EURUSD --start 2022-08-15 --end 2026-09-22 \
  --n-trials 100 --jobs 2 --seed 42 --report-dir ./reports/full_run \
  > /tmp/opt_run.log 2>&1 &
```

Мониторинг: `tail -f /tmp/opt_run.log` и `grep -c 'Trial.*finished' /tmp/opt_run.log`.
Остановка: `kill <PID>`. Номер процесса печатает команда запуска; если он потерян, процесс
находит команда `ps aux | grep run_optimization`.

Это правило обязательно для всех будущих запусков.

## Что уже сделано

Реализованы следующие слои.

Данные — `data_loader.py`: конвенция open_time, сшивка старшего таймфрейма (HTF) и младшего
(LTF) по закрытому бару.

Индикаторы — `indicators/structure.py` (свинги и BOS/CHoCH), `fvg.py`, `liquidity.py` (sweep),
`impulse.py` (фильтр импульса), `sessions.py` (killzone — торговые окна сессий), `bias.py`
(направленность по H1, H4 и D1), `levels.py` (PDH/PDL, PWH/PWL, PMH/PML и диапазоны азиатской,
лондонской и нью-йоркской сессий с фильтрами доступности и жизненным циклом fresh/broken).

Стратегия — `strategy/intents.py`: цепочка входа `sweep -> CHoCH -> displacement -> FVG limit`
(см. спецификацию проекта). Один интент на принятый бар (побеждает самый значимый уровень бара),
плюс журнал отказов. `strategy/take_profit.py`: ближайший видимый уровень ликвидности с фолбэком
по RR. `strategy/risk_gate.py`: проверка маржи и процент риска для набора интентов.

Бэктестер — `backtester/engine.py`: событийный движок (см. спецификацию проекта). Лимит
исполняется на баре после сигнала. Стоп система проверяет раньше цели. Издержки модель C6
спецификации списывает как спред и своп, плюс комиссия и слиппедж профиля. Маржинальный фильтр C7
она проверяет по текущей equity. Для каждого интента, не ставшего сделкой, есть строка в журнале.
`backtester/metrics.py`: таблица метрик.
`backtester/reports.py`: текстовая сводка и экспорт журнала сделок.

Walk-forward — `backtester/walkforward.py`: разбиение одной ленты на обучение и проверку.
`split_walkforward` режет якорные расширяющиеся фолды по умолчанию и скользящие при
`anchored=False`. Это позиционные срезы кадра заказчика, поэтому фолд никогда не делит бар со
своим окном обучения. `aggregate_fold_metrics` отдаёт среднее и сигму по генеральной совокупности
для шести главных метрик. `run_walkforward` соединяет фолды с движком при фиксированных
издержках и без оптимизации: подбор параметров — отдельная задача.

Оптимизатор — `optimizer/`: поиск параметров (см. спецификацию проекта). `build_tape_marks` кэширует
разметку bias старших таймфреймов и книгу уровней один раз на запуск для всех триалов
исследования. `score_from_aggregates` ранжирует один набор параметров по фолдам проверки: ведущая
метрика агрегата walk-forward умножается на профит проверки и делится на просадку, а при
`penalty_power` заказчика ещё приглушается тем, сколько прибыли обучения дожило до проверки. Окно
проверки, не заработавшее денег, получает ровно ноль, поэтому убыточный набор никогда не обгонит
прибыльный. Второй профиль — счёт M5: `trades_scaled_score` ранжирует набор по **пулу**
фолдов проверки (сумма выигрышей делить на сумму убытков, а не среднее отношений) и отказывается
читать период, где меньше пяти фолдов несут по три сделки и больше. Первый прогон M5 показал,
зачем это нужно: средний profit factor выбирал убыточный набор, потому что среднее поднимал один
фолд из четырёх сделок. `run_optimization` максимизирует этот счёт на исследовании TPE с
фиксированным seed по диапазонам `PARAM_RANGES` и заново переоценивает победителя по всем фолдам.
`cache_mismatches` отказывает конфигурации, из которой кэш не строился. optuna импортируется лениво,
фабрикой исследования, поэтому слой и его тесты работают и без неё.

Консоль — `scripts/`: раннеры проекта. `smc-backtest` выполняет один запуск фиксированной
конфигурации по окну и пишет отчёт. `smc-optimize` проводит исследование walk-forward и затем
отчитывается о победителе. Оба пишут в `./reports` и держат свой контракт командной строки. Ни
один из них не задаёт порог и не пересчитывает метрику: пороги и метрики живут в слое ниже.

Данные лежат в `./data/`, отчёты — в `./reports/`.

## Источники данных

Лента приходит из двух баз, их выбирает флаг `--data-source`:

- `project` (по умолчанию) — папка `./data` с раскладкой `datetime,open,high,low,close,volume`;
- `mt5` — сырой экспорт MetaTrader 5 «Bars»
  (`symbol,timeframe,time,open,high,low,close,tick_volume,spread,real_volume`).

Имя файла одно в обеих базах: `<SYMBOL>_<TIMEFRAME>.csv`, например `EURUSD_M15.csv`. Базу MT5
задаёт переменная `SMC_DATA_DIR`; без неё берётся `$HOME/_data/mt5` (то есть `~/_data/mt5`, а на
этой машине — `/home/com/_data/mt5/`). Раскладку `load_ohlcv` определяет по именам колонок,
поэтому переводить выгрузку руками не нужно. D1 в экспорте MT5 — голая дата, M15 и H1 — полный
штамп времени.

Запуск прямо на свежем экспорте брокера (режим A):

```bash
SMC_DATA_DIR=~/_data/mt5 smc-backtest --symbol EURUSD --hierarchy D1_H1_M15 \
  --start 2022-08-15 --end 2026-09-22 --data-source mt5
```

Повторный штамп времени в свежем экспорте не роняет запуск: система берёт позднюю строку
(`merge_ohlcv` в `smc_zero.data_loader`). Так четыре года проектной ленты и длинный экспорт
брокера становятся одной лентой без ручной конвертации.

Подробности — в спецификации проекта.

Перед длинным прогоном ленту проверяет `smc-check-tape`: он читает файл как раннер и
называет дубли меток, метки вне сетки таймфрейма, обрезку (баров меньше, чем торговых дней в
окне), дырки внутри торгового дня и самые тонкие дни.

```bash
SMC_DATA_DIR=~/_data/mt5 smc-check-tape --symbol EURUSD --timeframe M5 --data-source mt5
```

Код выхода: `0` — лента здорова, `1` — дефект, `2` — файл не читается. Флаг `--json` печатает
тот же отчёт машинно.

Лента M5 режима B должна покрывать около четырёх лет: walk-forward просит 15 фолдов. Диалог
«Сохранить как» в MetaTrader 5 останавливается примерно на 100 000 баров, то есть на 1.4 годах
M5, поэтому историю выгружает скрипт-помощник: `tools/mt5/ExportBars.mq5` вместе с инструкцией
`tools/mt5/README.md`.

## Ежедневный режим

Ежедневные сигналы готовит скрипт `scripts/daily_signal_check.sh`. Он работает в режиме A
(конфигурация по умолчанию — `configs/live_eurusd_m15.yaml`), читает ленту из свежего экспорта
MetaTrader 5 (флаг `--data-source mt5`, база `SMC_DATA_DIR`), запускает бэктест за последние
четыре года до текущей даты под `nohup`, кладёт отчёт в `./reports/daily_<ГГГГММДД>` и печатает
сделки, открытые с 22:00 MSK вчерашнего дня. Автоматического исполнения нет: сигналы человек
исполняет вручную и записывает результат в `docs/TRADING_JOURNAL.md`.

Скрипт берёт базу экспорта из переменной `SMC_DATA_DIR`, а по умолчанию читает `$HOME/_data/mt5`
(на этой машине — `/home/com/_data/mt5/`):

```bash
cd /home/com/work2/python/cfd/project/smc_zero
SMC_DATA_DIR=/home/com/_data/mt5 ./scripts/daily_signal_check.sh
```

Повторно напечатать сигналы готового отчёта, без нового бэктеста, можно так:

```bash
SMC_REPORT_FOLDER=./reports/daily_20261002/backtest_EURUSD_M15_2022-10-02_2026-10-02 \
  ./scripts/daily_signal_check.sh
```

Запуск по расписанию (будни, 22:00 MSK) оформляется строкой cron. Пути в строке ниже приведены
для этой машины; на другом окружении подставьте свои. Лог складывается в `/tmp/cron_smc.log`:

```
0 22 * * 1-5 SMC_DATA_DIR=/home/com/_data/mt5 /home/com/work2/python/cfd/project/smc_zero/scripts/daily_signal_check.sh >> /tmp/cron_smc.log 2>&1
```

Перед запуском убедитесь, что в папке экспорта лежат свежие `EURUSD_M15.csv` и, если они нужны
стратегии, `EURUSD_H1.csv` и `EURUSD_D1.csv`. Обновление выгрузки описано в разделе
[«Источники данных»](#источники-данных).

## Глоссарий

### Торговые концепции

- **SMC (Smart Money Concepts)** — подход к анализу рынка, который ищет следы крупных участников
  в структуре цены: сломы структуры, зоны дисбаланса и скопления ликвидности.
- **Bias** — направленность старшего таймфрейма, общий вектор рынка. Старший таймфрейм задаёт
  предпочтительное направление сделок, младший уточняет точку входа.
- **BOS (Break of Structure)** — слом структуры: закрытие цены за последний свинг по направлению
  тренда. Подтверждает продолжение движения.
- **CHoCH (Change of Character)** — смена характера движения: закрытие цены против тренда,
  которое ломает контр-свинг. Сигнализирует о возможной смене направления.
- **FVG (Fair Value Gap)** — зона дисбаланса, то есть трёхсвечный разрыв, где цена прошла без
  встречной торговли. Бычий FVG: `low[i+1] > high[i-1]`, медвежий — наоборот.
- **Order Block (OB)** — блок ордеров: последняя противоположная свеча перед импульсом, который
  дал BOS или CHoCH. Блок считают валидным, если импульс оставил смещение цены (displacement)
  или FVG.
- **Liquidity** — ликвидность: уровни скопления стоп-ордеров и лимитных заявок (равные максимумы
  и минимумы, PDH/PDL, границы сессий). Цена часто идёт к таким уровням.
- **Sweep** — снятие ликвидности (ложный пробой): тень выходит за уровень, а закрытие свечи
  возвращается внутрь. За снятием ликвидности обычно следует разворот.
- **Killzone** — активное торговое окно сессии (Лондон, Нью-Йорк), когда объём и волатильность
  повышены. В проекте задаётся в `indicators/sessions.py`.
- **Premium/Discount** — зона премии и дисконта относительно равновесия диапазона последнего
  структурного свинга. Лонг ищут в дисконте (ниже середины), шорт — в премии (выше середины).
- **PDH/PDL (Previous Day High/Low)** — максимум и минимум предыдущего дня. Служат целями и
  уровнями ликвидности.
- **AsianH/L, LondonH/L, NYH/L** — максимум и минимум азиатской, лондонской и нью-йоркской
  сессий. Используются как сессионные уровни ликвидности.

### Таймфреймы и структура

- **HTF (Higher Timeframe)** — старший таймфрейм, на котором задаётся bias. В режиме A его роль
  играют H1, H4 и D1; в режиме B — H4 и D1.
- **LTF (Lower Timeframe)** — младший таймфрейм, на котором ищут точку входа. В режиме A это M15,
  в режиме B — M5.
- **D1, H4, H1, M15, M5** — дневной, четырёхчасовой, часовой, 15-минутный и пятиминутный
  таймфреймы. В режиме A работают D1 (bias), H1 (структура) и M15 (вход); в режиме B — H4 и D1
  (bias), M15 (структура) и M5 (вход).
- **Swing (свинг)** — локальный экстремум: максимум или минимум с N свечей слева и справа.
  Свинг подтверждается закрытием правой свечи и известен только с этого момента.

### Иерархии и данные

- **Пресет иерархии (Hierarchy Preset)** — именованный набор трёх рабочих таймфреймов и кадра,
  на котором читают структуру. В проекте есть пресет `D1_H1_M15` (режим A) и пресет `H4_M15_M5`
  (режим B).
- **Слой структуры (Structure Layer)** — таймфрейм, на котором читают BOS и CHoCH, когда бар
  входа для этого слишком мелкий. В режиме B структура читается на M15 и становится доступна
  входу M5 только после закрытия бара M15.
- **Дни прогрева (Warmup Days)** — сколько дней ленты движок читает до начала окна, чтобы
  индикаторы старших таймфреймов набрали историю. Задаётся полем `run.warmup_days` в конфиге.
- **Агрегированный фактор прибыли (Pool Profit Factor)** — отношение суммы прибылей к сумме
  убытков по пулу плотных фолдов проверки, а не среднее отношений. Так один «полный» фолд
  не поднимает оценку набора.
- **Целевой счётчик сделок (Trade Target Score)** — счёт для отбора параметров режима B:
  агрегированный фактор прибыли умножается на долю набранных сделок от цели и падает до нуля
  ниже порога сделок, при убытке пула и при нехватке плотных фолдов.

### Метрики и параметры

- **Pip (пункт)** — минимальный шаг котировки; для EURUSD равен 0.0001.
- **Lot (лот)** — стандартный торговый объём; один лот равен 100 000 единиц базовой валюты.
- **RR (Risk/Reward)** — соотношение риска и прибыли. Показывает, во сколько раз возможная
  прибыль превышает риск по сделке.
- **Win Rate (доля прибыльных сделок)** — отношение числа прибыльных сделок к общему числу
  сделок, в процентах.
- **Profit Factor (фактор прибыли)** — отношение суммарной прибыли к суммарному убытку. Значение
  выше единицы означает прибыль на длинной дистанции.
- **Max Drawdown (максимальная просадка)** — наибольшее падение equity от пика, в процентах.
- **Sharpe Ratio (коэффициент Шарпа)** — доходность с поправкой на риск: отношение средней
  доходности к её волатильности. Чем выше, тем ровнее кривая капитала.

### Издержки

- **Spread (спред)** — разница между ценой покупки (ask) и ценой продажи (bid). Списывается с
  каждой сделки.
- **Slippage (проскальзывание)** — исполнение по цене хуже ожидаемой. Возникает на быстром рынке.
- **Swap (своп)** — плата брокера за перенос открытой позиции на следующий день.
- **Commission (комиссия)** — вознаграждение брокера за сделку. У счёта Альфа-Форекс комиссия
  равна нулю, заработок идёт со спреда.

### Разработка и тестирование

- **Walk-forward** — скользящая оптимизация с валидацией: параметры подбирают на одном окне
  (обучение), а проверяют на следующем, которое модель не видела.
- **OOS (Out-of-Sample)** — выборка для проверки вне оптимизации. Показывает, работает ли
  стратегия на данных, которые не участвовали в подборе.
- **Intent (намерение)** — кандидат в сделку: описание входа, которое цепочка правил построила,
  но движок ещё не превратил в сделку.
- **Gate (гейт)** — условие проверки, фильтр. Гейт может пропустить или отклонить кандидата,
  например по риску или по доступности уровня.
