# Журнал исполнения сигналов (ручной демо-прогон)

Этот файл — единственное место, где факт встречается с планом.
Скрипт `scripts/daily_signal_check.sh` печатает сигналы дня, человек исполняет их
на демо-счёте Альфа-Форекс и записывает результат сюда. Автоматического исполнения нет.

## Как вести журнал

1. В 22:00 MSK запустите проверку: `scripts/daily_signal_check.sh`.
2. Откройте отчёт дня: `./reports/daily_<ГГГГММДД>/backtest_EURUSD_M15_<начало>_<конец>/trades.csv`.
   План сделки берётся оттуда: колонки `entry`, `sl`, `tp`.
3. Исполните сигнал на демо-счёте вручную. Факт берётся из терминала брокера.
4. Заполните строку в тот же день. Пропущенный сигнал — тоже строка, причина идёт
   в «примечание».
5. В пятницу после закрытия посчитайте недельные метрики (раздел ниже) и сравните с бэктестом.

## Откуда берётся каждая колонка

| Колонка журнала | Источник |
| --- | --- |
| дата | день исполнения сигнала, MSK |
| сигнал | `trades.csv`: колонка `side` (`long` / `short`) |
| entry план, sl план, tp план | `trades.csv`: колонки `entry`, `sl`, `tp` |
| entry факт, sl факт, tp факт | терминал брокера: цена входа, стопа и тейка |
| комиссия факт | терминал брокера: комиссия за сделку в долларах |
| слиппедж факт | разница `entry факт` и `entry план` в пипсах (модуль) |
| profit факт | терминал брокера: результат сделки в долларах |
| примечание | пропуск, ручная правка цены, сбой связи, всё нештатное |

## Недельные метрики

Три показателя считаются по этому журналу, а не по бэктесту:

- **WR** (win rate, доля прибыльных сделок) — прибыльные сделки, делённые на все сделки;
- **PF** (profit factor, фактор прибыли) — сумма прибылей, делённая на модуль суммы убытков;
- **DD** (drawdown, просадка) — наибольшее падение equity от пика, в процентах.

## Критерий остановки

Остановка, если за последние 30 сделок любой показатель хуже ориентира более чем на 30 %:

- WR ниже 44.7 % (порог руководства «WR ниже 50 %» строже, поэтому действует он);
- PF ниже 1.44;
- DD выше 2.33 %.

После остановки: сверить свежесть котировок, фактические издержки и параметры конфига.
Повторный запуск — только после разбора и повторного бэктеста. Позицию без оптимизации
не увеличивать.
