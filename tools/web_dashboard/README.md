# Веб-дашборд

Standalone-витрина результатов бэктеста `smc_zero`. Инструмент читает уже готовый отчёт и
собирает один HTML-файл с интерактивными графиками Plotly.

## Что это и чем не является

Дашборд это слой отображения, а не часть торгового конвейера. Он **не** меняет стратегию,
движок, оптимизатор и конфиги. Всё, что он считает сам, — производные кривые из колонок
`trades.csv`: equity, просадка, помесячная прибыль, длительности, распределение RR и свечи с
разметкой входов. Числа, которые посчитал бэктестер, берутся из таблицы как есть.

Правило 4 проекта требует издержек: дашборд не показывает прибыльность без них. Он вообще не
делает выводов о прибыльности — это смотровая площадка над отчётом.

## Установка

Plotly вынесена в optional-набор `dashboard`, поэтому ядро и его тесты работают без неё.

```bash
pip install -e ".[dashboard]"
```

## Запуск

```bash
# демо: синтетические сделки и свечи, реальный отчёт не нужен
python tools/web_dashboard/scripts/generate_dashboard.py --demo

# реальный отчёт: папка с trades.csv (summary.txt желателен, но не обязателен)
python tools/web_dashboard/scripts/generate_dashboard.py \
  --report-dir ./reports/backtest_EURUSD_M15_2025-05-20_2026-09-22

# свечной график по своей ленте и нестандартный путь вывода
python tools/web_dashboard/scripts/generate_dashboard.py \
  --report-dir ./reports/<отчёт> --tape ./data/EURUSD_M15.csv \
  --output ./tmp/dashboard_with_tape.html

# сравнение двух отчётов: таблица KPI, общие кривые и радар
python tools/web_dashboard/scripts/generate_dashboard.py \
  --report-dir ./reports/<отчёт-A> \
  --compare ./reports/<отчёт-A> ./reports/<отчёт-B>
```

## Флаги

| Флаг | Смысл |
| --- | --- |
| `--demo` | синтетические сделки и свечи; несовместим с `--report-dir` |
| `--report-dir DIR` | папка отчёта с `trades.csv`; допустим и корень с единственной подпапкой |
| `--output PATH` | путь итогового HTML; относительный путь считается от корня репозитория |
| `--title TEXT` | заголовок страницы и вкладки |
| `--tape PATH` | CSV с OHLC-лентой (`datetime`, `open`, `high`, `low`, `close`) для свечей |
| `--compare A B` | сравнительная секция для двух папок отчётов |
| `--inline-plotly` | вшить Plotly в HTML вместо загрузки с CDN (страница работает офлайн) |

Нужен хотя бы один источник: `--demo`, `--report-dir` или `--compare`. При одном `--compare`
основной отчёт берётся из первой папки.

## Куда попадает страница

Страница это временный артефакт, поэтому по умолчанию она ложится в `./tmp/` проекта:

| Режим | Путь по умолчанию |
| --- | --- |
| `--demo` | `tmp/dashboard_demo.html` |
| `--report-dir`, `--compare` | `tmp/dashboard.html` |

Относительный `--output` считается от **корня репозитория** — папки с `pyproject.toml`, а не от
текущего каталога. Поэтому запуск из любой папки пишет внутрь проекта, а не создаёт `./tmp` рядом
с собой. Абсолютный путь берётся как есть (на этом стоят тесты). Каталог вывода создаётся
автоматически. `tools/web_dashboard/public/dashboard.html` остаётся удобным местом для итоговой
страницы — но только через явный `--output`.

## Временные артефакты

Всё непостоянное по проекту складывается в `./tmp/`: логи прогонов, демо-страницы, черновики
сообщений коммитов, диагностические выводы. Каталог игнорируется git (в нём лежит только
`.gitkeep`), поэтому мусор не попадает в коммиты. Системный `/tmp` для этого не годится: он
очищается при перезагрузке и смешивает файлы проекта с чужими процессами. Постоянные результаты
идут в `./reports/`, данные — в `./data/`.

## Входные данные

Обязательный минимум `trades.csv`: колонка времени (`fill_time` или `open_time`) и `profit`.
Остальные колонки необязательны, их отсутствие лишь убирает часть графиков и добавляет заметку
на странице:

| Колонка | Что даёт | Если её нет |
| --- | --- | --- |
| `exit_time` | длину отрезков SL/TP на свечах | отрезки рисуются от входа |
| `result` | donut Win / Loss и цвет точек RR | панель пропускается с заметкой |
| `rr` | график Risk / Reward | панель пропускается с заметкой |
| `limit_dur_min` | длительность сделок в минутах | берётся `bars_held` × минуты бара |
| `bars_held` | то же, если нет `limit_dur_min` | панель пропускается с заметкой |
| `side`, `entry`, `sl`, `tp` | разметка входов на свечах | свечи рисуются без меток |

`summary.txt` тоже необязателен. Из него берутся символ, таймфрейм, окно, `sharpe (per bar)`,
`max drawdown` и `initial capital`. Без файла символ и таймфрейм приходят из имени папки вида
`backtest_<СИМВОЛ>_<ТФ>_<НАЧАЛО>_<КОНЕЦ>`, Шарп показывается как «—», а просадка в процентах
считается от начального капитала; если капитала нет, выводится абсолютная просадка в USD.

Пустой `trades.csv` (одна шапка) не ошибка: страница собирается с заметкой «Сделок в отчёте
нет». Отсутствие папки отчёта или `trades.csv` даёт понятную ошибку с путём к файлу.

## Что показывает страница

Панель KPI (символ, таймфрейм, окно, сделок, прибыль, profit factor, win rate, max drawdown,
Sharpe, источник) и панели графиков: equity, drawdown, помесячная прибыль, Win / Loss,
длительность сделок, Risk / Reward, свечи с разметкой входов и таблица последних 50 сделок.
В режиме сравнения добавляются сравнительная таблица KPI, две кривые equity и радар по
нормализованным метрикам (просадка инвертирована: меньше — лучше).

Заметки над графиками честно объясняют, почему панель пропущена.

## Plotly: CDN или встроенная копия

По умолчанию страница подключает Plotly с `cdn.plot.ly` — файл получается десятки килобайт
и требует интернет при открытии. Флаг `--inline-plotly` вшивает библиотеку внутрь HTML:
страница работает офлайн, но весит от 3 МБ.

## Тесты

```bash
pytest tests/test_web_dashboard.py
```

Шесть проверок: демо-режим и CDN, KPI из таблицы и summary, отсутствие `summary.txt`, пустой
`trades.csv`, режим сравнения и понятные ошибки на кривом входе. Седьмая проверка — резолв
дефолтного вывода: путь ведёт в `./tmp` корня репозитория и не зависит от текущего каталога.
Если Plotly не установлена, файл пропускается через `pytest.importorskip("plotly")`.

## Ограничения

* Свечной график требует ленты: в `trades.csv` свечей нет, поэтому без `--demo` или `--tape`
  панель пропускается. Придумывать свечи из сделок нельзя.
* До 1500 последних свечей (`MAX_CANDLES`) и до 10 размеченных сделок (`MAX_MARKED_TRADES`):
  больше делает HTML неподъёмным.
* Графики строятся по закрытым сделкам из отчёта, поэтому вопрос lookahead к дашборду
  не относится — все числа приходят из уже посчитанного бэктеста.
